# salintrusion_tool

An interactive map viewer for NEREIDA's monthly seasonal saline water
intrusion (SWI) forecast at groundwater wells along the Ter and Tordera
coastal aquifers (Catalonia).

Live at the repo's GitHub Pages URL (root `index.html`, no build step).

## What it shows

A split-screen Leaflet map: wells are plotted from `swi_wells.json`
(code, basin, coordinates, depth, distance to coast), colour-coded by
forecast risk of saline intrusion for the selected month:

- 🟢 Low risk — P(intrusion) < 33%
- 🟡 Medium risk — 33–66%
- 🔴 High risk — P(intrusion) > 66%

Pick a well on the map, pick a year/month from the selectors (or **Darrera
previsió** to jump to the latest available), and the right-hand panel loads
that well's density forecast plot for the selected month.

## Repository layout

```
index.html                     The viewer (map + well markers + plot loader)
swi_wells.json                 Well metadata: code, basin (ter/tordera),
                                lon/lat, screen depth, distance to coast
density_plots/<year>-<month>/  One folder per forecast month (1995-01 onward),
                                containing swi_<basin>_<well-code>.png for
                                every well
seasonal/verification/         skill_scores_swi.csv — skill-score reference
                                table, carried alongside the plots
```

`index.html` resolves each well's plot as
`density_plots/<selected-month>/swi_<basin>_<well-code>.png` — adding a new
month only requires a new `density_plots/<year>-<month>/` folder with plots
named the same way as the existing ones.

## Data source and updates

The forecast is generated by the seasonal pipeline in
[`NEREIDACA/main`](https://github.com/NEREIDACA/main): river/reservoir
seasonal forecasts (Copernicus SEAS5.1 → GR4J) feed a CatBoost-based SWI
risk model per well, calibrated against historical conductivity/chloride
observations (`codes/run_seasonal_swi.R`, `codes/generate_swi_plots.R`,
`codes/export_swi_wells_json.R`). This repo has no logic of its own beyond
the map/viewer — it is a publish target.

It is updated automatically by `main_operational.sh` in that pipeline on
each monthly run:

1. The new month's SWI forecast is generated and its density plots written
   to `tool/density_plots/<year>-<month>/` (files named `swi_*.png`).
2. `tool/swi_map_viewer.html` is copied here as `index.html`.
3. `tool/swi_wells.json` is copied here as `swi_wells.json`.
4. That month's `swi_*.png` plots are copied into
   `density_plots/<year>-<month>/`.
5. This repo is committed and pushed automatically.

No manual step is normally required; to publish a month out of band, mirror
those same copy steps by hand.
